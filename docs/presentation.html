Question 01
어떤 문제를 해결하려는가?
보험 시장의 정보 비대칭 문제
Problem Definition
💡
한국 보험 시장 규모는 200조 원 이상이지만, 소비자는 수백 개 상품을 직접 비교해야 하고 설계사에게 의존하면 수수료 구조로 인한 편향 추천이 발생합니다. 공시 데이터는 존재하지만 비전문가가 해석하기 어렵습니다.
Pain Point 1
🔍 정보 과부하
생명보험·손보사 합산 수천 개 상품. 보험다모아·보험사 홈페이지를 직접 비교하려면 수십 시간 소요
Pain Point 2
📉 갱신형 함정
갱신형 보험은 초기 보험료가 낮아 보이지만 5~10년 후 2~5배 인상. 소비자가 장기 비용을 예측하기 어려움
Pain Point 3
💳 신용도별 맞춤 전략 부재
신용점수에 따라 가입 가능한 보험이 다름. 일반 심사 통과 불가 시 무심사 상품으로 전환 필요하나 안내 부족
Solution
🤖 AI 중립 상담사
수수료 이해관계 없이 공시 데이터 기반 중립적 비교·추천. 신용점수·나이·예산을 통합 반영한 포트폴리오 제안

Question 04
어떤 데이터를 사용할 것인가?
공식 공시 데이터 + 실시간 웹 + 신용평가 기관 통합
Data Sources
📊 보험다모아 공시 엑셀
보험협회(생명+손해) 공동 운영 e-insmarket.or.kr에서 제공하는 표준 보험료 XLS 파일. 연령·성별별 실제 납입 보험료 포함. 종신·실손·암·치아·간병보험 커버.
★★★★★ 공식 공시
🏛️ FSS 금융감독원 API
finlife.fss.or.kr 공식 Open API. 연금저축보험 상품 데이터 실시간 조회. 무료 신청 (당일~익일 승인). 24h 캐시로 API 호출 최소화.
★★★★★ 정부 공식 API
🌐 DuckDuckGo 웹 검색
ddgs 라이브러리로 실시간 뉴스·비교 정보 검색. API 키 불필요. 2025/2026 연도 키워드 자동 포함으로 최신 정보 우선 수집.
★★★☆☆ 실시간 검색
💳 NICE / KCB 신용점수
Chrome CDP 모드로 NICE 지키미(credit.co.kr) 또는 올크레딧(allcredit.co.kr)에서 실시간 스크래핑. 또는 사용자가 토스·카카오페이에서 확인 후 직접 입력. NICE·KCB 동시 입력 시 평균 산출.
★★★★★ 실시간 / 직접 입력
📚 보험 지식베이스 (RAG)
실손·암·종신·연금보험 구조·약관·용어 설명 내장 데이터. ChromaDB 벡터 DB로 인덱싱. 엑셀 데이터에서 자동 생성 스크립트 포함 (build_knowledge_from_excel.py).
★★★★☆ 내장 지식
🔄 보험다모아 실시간 스크래핑
Playwright CDP 모드로 e-insmarket.or.kr 직접 수집. mbuster 봇 차단 우회. 30/40/50세 × 남/여 6가지 조합 사전 수집 후 24h 캐시. 엑셀 대비 보완 데이터.
★★★★☆ CDP 스크래핑

Summary
📊
공식 데이터 기반
보험다모아(보험협회 공식)·FSS(금융감독원) 공시 데이터로 신뢰할 수 있는 보험료 제공. 출처와 신뢰도를 모든 답변에 명시.
🤖
멀티 도구 에이전트
단순 챗봇이 아닌 8가지 전문 도구를 자율적으로 선택·조합하는 Tool Calling 에이전트. 상황에 따라 최적 데이터 소스 자동 선택.
💳
신용점수 개인화
NICE/KCB 5등급 신용 모델로 개인 신용도에 맞는 보험 포트폴리오 차별화. 무심사·간편심사 상품까지 통합 추천.
⚡
실시간 스트리밍
Flask SSE로 GPT-4o 답변을 토큰 단위로 즉시 출력. 도구 호출 단계(검색 중, 분석 중)를 UI에 실시간 표시하여 투명한 처리 과정 공개.
🔄
Graceful Fallback
API 키 없으면 Mock 모드, 스크래핑 차단되면 로컬 엑셀, ChromaDB 없으면 키워드 검색. 어떤 환경에서도 동작하는 다중 fallback 체계.
📈
확장 가능 구조
새 도구(Tool)를 추가하면 오케스트레이터가 자동으로 활용. 보험 외 금융 상품(대출·펀드)으로 확장 가능한 에이전트 아키텍처.
